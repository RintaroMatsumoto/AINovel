# narrative-writer に渡す参照ファイルの特定手順

> 各章の執筆前に、narrative-writer に何を渡すべきかを漏れなく特定するための手順書。
> 2026-07-07 策定（第1章の反省より：祖父・叔母の設定ファイルを渡し忘れた）。
> **本手順書は `執筆ワークフロー_v2.md` の Step 0 の補助資料として使用する。**

## 基本原則

- **設定ファイルはあるだけ渡せばいいのではない。その章に実際に登場するキャラと、語り手の内面に関わる設定だけを選ぶ。**
- 不要なファイルを渡すと narrative-writer のコンテキストを圧迫し、精度が落ちる。
- 渡し漏れはキャラの声や事実関係のブレに直結する。
- **どんなに準備しても間違いは起きる。書かれた後に consistency-checker で必ず検証すること。**（Step 8）

## 手順

### Step 1: 細綱から登場人物を列挙する

細綱の「登場人物と登場順」セクションを読み、**全員をリストアップ**する。

```
例（第1章）:
誠（語り手）→ 上司 → 同僚たち →（回想）叔母・祖父・幼い栞
→（現在②）家族の顔が浮かぶ（百合子、栞、翼）
```

**注意**: 「家族の顔が浮かぶ」のような間接的な登場も含める。語り手の内省に登場するキャラも、その描写には設定が必要。

### Step 2: キャラごとに設定ファイルの有無を調べる

```bash
ls novels/設定/キャラクター/
```

| キャラ | 設定ファイル | 対応 |
|--------|:--:|------|
| 橘誠 | `橘誠.md` | ✅ 必ず渡す（語り手） |
| 上司 | なし | 汎用キャラ。渡す必要なし |
| 同僚たち | なし | 同上 |
| 叔母 | なし | `橘誠.md` L19-22 に行動記述あり。該当箇所を指示 |
| 誠の祖父 | `誠の祖父.md` | ✅ 渡す（回想の核心） |
| 幼い栞 | `橘栞.md` | ✅ 渡す（幼少期の声と行動の根拠） |
| 橘百合子 | `橘百合子.md` | ✅ 渡す（語り手の記憶の中の妻） |
| 橘翼 | `橘翼.md` | ✅ 渡す（同上） |

**ファイルがないキャラの扱い**:
- `橘誠.md` の該当行を grep で探す: `grep -n "叔母" novels/設定/キャラクター/橘誠.md`
- `関係.md` で関係性を確認: `grep -n "叔母" novels/設定/関係.md`
- ファイルがないことを narrative-writer に明示する（「叔母の独立設定ファイルはない。橘誠.md L19-22 を参照」）

### Step 3: 語り手の設定を必ず入れる

語り手のキャラファイルは**常に必須**。7次元言語スタイル・声の定義・進捗態度が本書の文体を決定する。

### Step 4: 層の構成から必要な世界観ファイルを判断する

細綱の「層の構成」テーブルを見て、回想・滲み出し・封筒の有無を確認。

| 層の種類 | 必要な追加ファイル |
|---------|-----------------|
| 回想に封筒が登場 | `破壊キャンペーン.md` |
| 回想に人形・ノートが登場 | `橘誠.md`（人形発見の経緯 L15-27）＋ `誠の祖父.md` |
| 滲み出し層がある | `橘百合子.md`（レイプ・脅迫の経緯）＋ `破壊キャンペーン.md` |
| 現在層のみ | 追加世界観ファイル不要 |

### Step 5: 構造ファイルは原則毎回渡す

| ファイル | 必須/条件付き | 理由 |
|---------|:--:|------|
| `文体プロファイル.md` | ✅ 必須 | 文体方針・4原理・誠/栞/翼の声の定義。**これを渡さないと旧方針（抑制）で書かれる** |
| `核心設定.md` | ✅ 必須 | 語り手の核心動機。地の文の基底感情を決定する |
| `関係.md` | 条件付き | 複数キャラが交差する章では必須。単独内省の章では不要 |
| `banned-words.md` | ✅ 必須 | 禁用語チェック |
| `anti-ai-writing.md` | ✅ 必須 | AI臭防止 |

### Step 6: 前章の末尾を渡す

前章の最終段落（最低100〜200字）を narrative-writer に渡し、文体と時間の継続性を確保する。

## チェックリスト

各章の執筆前に以下を確認する:

```
□ Step 1: 細綱の登場人物を全員リストアップしたか
□ Step 2: 各キャラの設定ファイルの有無を確認したか
□ Step 3: 語り手のキャラファイルを入れたか
□ Step 4: 層の構成から世界観ファイルの要否を判断したか
□ Step 5: 構造ファイル4点（文体プロファイル・核心設定・banned-words・anti-ai-writing）を入れたか
□ Step 6: 前章末尾を入れたか
□ ファイルがないキャラについて、代替の参照先（橘誠.md の該当行 / 関係.md）を明示したか
```

## 書いた後の工程

### Step 7: consistency-checker でファクトチェック

執筆後、必ず consistency-checker を spawn して事実矛盾を検出する。

```
spawn: consistency-checker
入力:
  - 初稿ファイルパス
  - 全キャラ設定ファイル
  - 細綱
  - 核心設定.md

チェック観点:
  1. 職位・年齢・物品の所在 — 設定との一致
  2. 時間線 — 「最後の通勤」なのにまだ退職まで1ヶ月ある等
  3. 視点整合性 — 語り手が知りえない情報の混入
  4. 伏線状態 — 埋設漏れ・誤った回収
  5. 場所・情景 — 設定との矛盾

出力: S1-S4 グレードの矛盾レポート
  S1 = 致命的（必ず修正）
  S2 = 重大（修正推奨）
  S3 = 軽微（任意）
  S4 = 情報（伏線状態等）

S1/S2 がある場合: narrative-writer を再 spawn して修正
S1/S2 がない場合: Step 8（品質チェック）へ
```

### Step 8: 品質チェックと追跡更新

全工程は `novels/参考/執筆ワークフロー_v2.md` Step 4 を参照。

```
メインAIが実行:
  1. 字数検証（5,000〜8,000字）
  2. 章末チェック（余韻）
  3. 元情報スキャン
  4. 標点正規化
  5. 禁用語スキャン
  6. 感情目標達成度（0-10, 6未満→報告）
  7. 村上文体精錬
  8. 追跡更新（chapter-extractor の抽出結果を下書きに）

ユーザー確認:
  - 文体・声の一貫性
  - キャラ行動の違和感
  - リズム・テンポ
```
