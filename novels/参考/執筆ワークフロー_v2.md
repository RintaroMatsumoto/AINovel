# 執筆ワークフロー v2

> 全工程エージェント委任版。メインAIは書かない。確認と判断のみ。
> 2026-07-07 策定。v1（メインAIが書く＋仕上げる）からの全面改訂。

## 役割分担

| 役割 | 担当 | 
|------|------|
| 執筆（初稿） | narrative-writer |
| 事実チェック | consistency-checker |
| 要約抽出 | chapter-extractor |
| 設定修正反映 | narrative-writer（再spawn） |
| 参照探索 | story-explorer |
| 最終品質チェック | メインAI |
| 最終判断（文体・声・修正要否） | ユーザー |
| 巻末レビュー | story-review full |

## 1章あたりのパイプライン

### Step 0: 引継ぎ準備（story-explorer）

```
spawn: story-explorer
入力:
  - 細綱ファイルパス
  - 「本章に登場する全キャラの設定ファイルを特定し、
     必要な参照ファイルの一覧をJSONで返せ」
出力:
  - 参照ファイルパッケージ（パスのリスト）
  - 前章末尾（自動取得）
```

### Step 1: narrative-writer（初稿）

```
spawn: narrative-writer
入力:
  - 細綱（Step 0 で特定）
  - キャラ設定ファイル（Step 0 で特定、全員分）
  - 文体プロファイル.md（必須・常に）
  - 核心設定.md（必須・常に）
  - 関係.md（複数キャラ出現時）
  - 前章末尾（Step 0 で取得）
  - banned-words.md / anti-ai-writing.md（必須・常に）
  - 世界観ファイル（回想・封筒・滲み出し層がある場合のみ）

指示テンプレート:
  """
  タスク: {巻名} 第{X}章 初稿執筆
  出力: novels/{巻名}/本文/第{X}章_初稿.md

  核心イベント: {細綱から}
  層の構成: {細綱から}
  感情の変化: {細綱から}
  結末: {細綱から}

  文体指示:
  - 自然な時間交差（境界マーク禁止。動詞の時制・光の質・温度感覚の変化のみで移行）
  - 激しい感情の人間ドラマ（愛・怒り・悲しみ・疑念を恐れずに描く）
  - 感情はラベリングせず、内省の過程と行動・身体反応で描く
  - 4原理（枷と愛／感情を恐れない／描かないことで描く／弱さの肯定）
  - 章末は総括・教訓・哲理禁止。余韻で閉じる
  - 字数: 5,000〜8,000字

  前章接続: {前章末尾}
  """
```

### Step 2a: consistency-checker（並列実行）

```
spawn: consistency-checker
入力:
  - 本文_第X章_初稿.md
  - 全キャラ設定ファイル（Step 0 のリスト）
  - 細綱
  - 核心設定.md

指示テンプレート:
  """
  チェック範囲: {初稿ファイルパス}
  キャラ設定: {Step 0 のファイルリスト}

  以下の観点で事実矛盾を S1-S4 グレードで検出せよ:
  1. 職位・年齢・物品の所在 — 設定との一致
  2. 時間線 — 章の時点と記述の整合性（例: 「最後の通勤」なのにまだ退職まで1ヶ月ある）
  3. 視点整合性 — 語り手が知りえない情報の混入（例: 誠が人形に見覚えがないのに母のものと断定）
  4. 伏線状態 — 埋設漏れ・誤った回収
  5. 場所・情景 — 設定との矛盾

  グレード:
  S1 = 致命的矛盾（必ず修正）
  S2 = 重大矛盾（修正推奨）
  S3 = 軽微（任意修正）
  S4 = 情報（伏線状態等、修正不要）
  """
```

### Step 2b: chapter-extractor（並列実行）

```
spawn: chapter-extractor
入力:
  - 本文_第X章_初稿.md

指示テンプレート:
  """
  抽出範囲: {初稿ファイルパス}

  以下を構造化して出力せよ:
  1. 要約（200字以内）
  2. 情節点（箇条書き。各1行）
  3. 登場キャラ一覧（出現順）
  4. キャラごとの状態変化（あれば）
  5. 新規埋設伏線（あれば）
  6. 感情の起点→終点
  """

出力用途: Step 4 の追跡更新の下書きとして使用
```

### Step 3: narrative-writer 再spawn（修正）

```
条件: consistency-checker のレポートに S1 または S2 がある場合のみ実行。
      S1/S2 がなければ Step 4 へスキップ。

spawn: narrative-writer（修正モード）
入力:
  - 本文_第X章_初稿.md
  - consistency-checker の S1/S2 レポート
  - Step 0 の全設定ファイル（再参照）

指示テンプレート:
  """
  タスク: 初稿の事実修正

  修正対象: 以下の S1/S2 項目「のみ」。それ以外の文章は一切変更しないこと。
  {consistency-checker の S1/S2 レポートを貼り付け}

  出力: novels/{巻名}/本文/第{X}章_修正稿.md
  """
```

---

### Step 4: メインAI + ユーザー 最終チェック

```
入力:
  - 本文（修正稿、または S1/S2 なしの場合は初稿）
  - chapter-extractor の抽出結果
  - consistency-checker のレポート（S3/S4 参照）

メインAIが実行する品質チェック:
  1. py で字数カウント（5,000〜8,000字）
  2. 章末チェック（総括・教訓・哲理の有無 → あれば指摘）
  3. 元情報スキャン（「第X章」「計画」「伏線」「読者」等の工程語混入 → あれば指摘）
  4. 標点正規化（node .agents/skills/story-long-write/scripts/normalize-punctuation.js {本文}）
  5. 禁用語スキャン（banned-words.md 参照。万能比喩・章末総括がヒットしたら指摘）
  6. 感情目標達成度チェック（細綱の感情目標に対し 0-10 で自己評価。6未満ならユーザーに報告）
  7. 村上文体の精錬（声の一貫性・自然な時間交差・余韻の確認。問題があれば指摘）
  8. 追跡更新（伏線.md / キャラ状態.md / 文脈.md — chapter-extractor の抽出結果を下書きに使用）

ユーザーに確認を仰ぐ項目:
  - 文体・声の一貫性に問題はないか
  - キャラの行動に違和感はないか
  - 章のリズム・テンポは適切か
  - 感情目標達成度 6 未満の場合 → 書き直すか、目標を見直すか

出力:
  - 本文_第X章.md（完成稿）
  - 追跡ファイル更新
```

## 巻末

```
条件: 全章完了時

実行:
  1. story-review full spawn（4 reviewer agent）
  2. 伏線債務最終計算: CC = active伏線数 - resolved伏線数。CC > 2 → ユーザーに警告
  3. 全章の感情弧線を確認し、巻全体のリズムを検証
  4. 滲み出し層の開示順序が設計通りか確認
```

## メインAI と ユーザーの判断が必要な場面

| 状況 | メインAIの行動 | ユーザーの判断 |
|------|-------------|-------------|
| S1/S2 レポートの内容が微妙 | レポートを提示し、修正案を示す | 修正する／しないを決定 |
| 感情目標達成度 6 未満 | 数値と理由を報告 | 書き直す／目標を見直す |
| 文体の精錬方向（もっと削る／足す） | 現状分析を提示 | 方向性を指示 |
| 巻末: CC > 2（伏線負債過重） | 警告と回収候補リストを提示 | 新規伏線停止／回収優先を判断 |
| 巻末: 感情弧線が単調 | データを示し警告 | 次の巻の感情設計を調整 |
