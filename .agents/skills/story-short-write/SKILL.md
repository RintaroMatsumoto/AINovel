# story-short-write：短編網文写作

あなたは短編網文写作実行器です。構想から完成原稿まで、1編の完全な短編小説を仕上げます。

**実行ルール：短編は感情を目標とし、全ての内容は感情に奉仕する。**

---

## 実行ルール

1. **先に感情を決め、次にストーリーを決める**。執筆前に目標感情（切ない/反転衝撃/爽快感/癒し/戦慄/共鳴感動）を確定必須、全内容がこの感情に奉仕する。
2. **1つの反転が1編を支える**。全ての伏線は反転に奉仕し、全ての感情は反転のために力を貯める。多線展開せず、世界観を敷かない。
3. **全ての文に意味がなければならない**。プロットを推進せず、反転の伏線を敷かず、感情を高めない文 → 削除。
4. **冒頭3文で生死が決まり、结尾で伝播が決まる**。冒頭にはフックが必須、结尾には余韻が必須。
5. **デフォルトは一人称**。短編網文（塩選/七猫短編など）の大多数は一人称を使用し、没入感が最も高い。題材が明確に三人称を必要とする場合（多視点サスペンスなど）を除き、一律「私」を使用。

---

## フォーマット規範（最優先）

詳細ルールは `references/format-and-structure.md` 参照、執筆前に必ず読み込む。**主セッションと narrative-writer サブエージェントは同一の本文フォーマットを使用する**：本文は `正文.md` にのみ保存、本文の隣接段落間は単一改行 `\n` のみ許可（空行/`\n\n` 禁止）、会話引用符スタイルはプロジェクト/プラットフォームの取り決めに従って統一（デフォルト半角二重引用符、塩選は「」も可）、短編の節マークは全文統一（デフォルト `###1.`/`###2.`）。サブエージェントの出力が主セッションのフォーマットと一致しない場合、本フォーマット規範に従って再配置してからファイルに書き込む。

---

## 核心メソッド

上記の実行ルールに加え、構想と執筆時には以下に従う：

- **検証済みのパターンから出発する**：对标書があれば先に分析し、なければ題材フレームワーク（genre-catalog.md）から対応するプロットパターンを見つける
- **モジュールを組み立てて使う**：伏線セクション、昇格セクション、反転セクションにはそれぞれ成熟した書き方がある。再発明しない。genre-writing-formulas.md の対応題材を参照
- **必要な情報のみ読み込む**：各節を書く前に目標感情と使用する技法を明確にし、答えられなければ先に参考資料を読み直す

## 写作フロー

### Phase 1：感情目標の確定

ユーザーに質問：**「読者に読後にどんな感情を抱かせたいですか？書きたい題材の方向性やインスピレーションはありますか？」**

ユーザーに明確なアイデアがある場合 → 直接 Phase 2 へ。

ユーザーが曖昧な場合 → ユーザーの感情選択を支援：

| 感情タイプ | 適したシーン | 難易度 | 市場热度 |
|----------|----------|------|----------|
| 切ない | 虐恋、後悔、すれ違い | 中 | 🔥🔥🔥 |
| 反転衝撃 | サスペンス、身分すり替え | 高 | 🔥🔥🔥 |
| 爽快感 | 溜飲、逆転 | 低 | 🔥🔥 |
| 癒し | 成長、家族愛、友情 | 中 | 🔥🔥 |
| 戦慄 | サスペンス、心理 | 高 | 🔥 |
| 共鳴感動 | 現実、職場、結婚 | 中 | 🔥🔥🔥 |

---

### Phase 2：核心フレームワークの構想

> ユーザーに参考小説がある場合、先に `/story-short-analyze` で分析する。デフォルト出力はプロジェクトルート `拆文库/{書名}/` に保存；ユーザーが現在の短編の参照ディレクトリを指定した場合、`{短編タイトル}/对标/{書名}/` に出力/同期可能。写作時にこれらの分析結果が自動的に検索・読み込まれるため、ユーザーが手動で prompt にコピーする必要はない。

#### 对标コンテキスト読み込み

> **拆文库/对标関係**：`拆文库/` = analyze skill の元の成果物（データソース）、プロジェクトルートに配置。`对标/` = 現在の短編の参照ビュー、`{短編タイトル}/对标/` に配置。短編写作は優先的に `{短編タイトル}/对标/{書名}/` を読み取り、なければプロジェクトルート `拆文库/{書名}/` にフォールバック、さらに `{短編タイトル}/拆文库/{書名}/`（旧構造互換）にフォールバック。

推奨ディレクトリ構造：

```
プロジェクトルート/
├── 拆文库/
│   └── {書名}/
│       ├── 拆文报告.md
│       ├── 情节节点.md
│       └── 写作手法.md
└── {短編タイトル}/
    ├── 设定.md
    ├── 小节大纲.md
    ├── 正文.md
    └── 对标/
        └── {書名}/
            ├── 拆文报告.md
            ├── 情节节点.md
            └── 写作手法.md
```

作業ディレクトリ下に `对标/` またはプロジェクトルートに `拆文库/` が存在するか、ユーザーが参考小説に言及した場合：

1. 上記の順序で `拆文报告.md`、`情节节点.md`、`写作手法.md` を検索
2. 核心的発見を読み取り：構造段落、感情曲線、反転位置、伏線の敷き方、句式リズム、参考になる技法
3. 本篇の `设定.md` の「对标概要」エリアに書き込み、写作時に各シーンから 1-2 の関連技法を呼び出す
4. 原文のみ見つかり分析レポートが見つからない場合、ユーザーに先に `/story-short-analyze` を実行するよう促す；ユーザーが続行を希望する場合、原文のみで弱い参考としても可

> **分析成果物のフォーマット**：analyze が格納する完全ファイルツリー、`_meta.json` schema、Stage→ファイルマッピング、および「story-short-write がこれらの成果物をどう読み取るか」の下流消費規範は [references/output-contract.md](references/output-contract.md) 参照。

<!-- cross-book-recall:trigger:structure-positioning -->
> **对标書が複数ある場合**：`references/cross-book-recall.md` 参照、副对标を「对标概要」エリアに anchor

#### Agent 呼び出し：story-architect

構想段階で、プロジェクトが story-architect agent をデプロイ済みの場合（`.opencode/agents/story-architect.md` の存在確認）、`Agent(subagent_type: "story-architect", prompt: "プロジェクトディレクトリ：{dir}\nタスクタイプ：短編構想\nクエリパラメータ：{感情目標+題材方向}")` を spawn してフレームワーク設計を補助可能。agent が利用不可の場合は主スレッドが直接実行。

ユーザーの短編の核心フレームワークを確定：

```
## 短編核心フレームワーク

### 基本情報
- タイトル（仮）：{}
- 目標字数：{} 字（短編通常 8000-20000 字）
- 目標プラットフォーム：{}
- 感情目標：{読者の読後感}

### 一言梗概
{主人公 + 困境 + 反転 + 感情の落ちどころ}

### 核心反転
- 反転タイプ：{身分反転/視点反転/動機反転/時間線反転}
- 反転内容：{一言説明}
- 伏線の手がかり：{最低3つの伏線ポイント}

### 感情設計
- 冒頭感情：{}（強度 {1-10}）
- 中盤感情：{}（強度 {1-10}）
- 反転感情：{}（強度 {1-10}、ピーク維持 ≥2節）
- 结尾感情：{}（強度 {1-10}）
- 反転の高潮は急降下させない：反転前1節から昇温開始、反転節でピーク到達、反転後1節でピーク維持、急降下させない

### キャラクタースケッチ
- 主人公：{一言キャラ設定}
- キーキャラクター：{一言キャラ設定}
- 関係：{彼らの間の関係}
```

フレームワーク確定後、設計タスクを完了し、作業ディレクトリ下にファイルを作成。

#### 設計タスク（フレームワーク確定後に実行）

詳細手順とテンプレートは `references/writing-workflow.md` 参照。構想時は目標感情からプロットを逆算し、インスピレーションから順方向に構築しない。順番に完了：

1. 貫通アイテムの設計（1-2個）→ `writing-craft.md` を読み込み
2. 敵対者の設計（ある場合）→ `villain-and-reveal.md` を読み込み
3. 暴露方法の確定 → 同上
4. 小节大纲.md の作成（フォーマットは writing-workflow.md 参照）：短編は軽量ブループリントのみ、各節に構造セクション/五段機能、人物/関係変化、因果/論理連鎖、结尾承接/フックを含め、長編の完全な章ブループリントは使わない
5. 反転情報差の検証（公式は writing-workflow.md 参照）
6. 伏線振り返りチェックリスト（基準は writing-workflow.md 参照）

#### Agent 呼び出し：character-designer

設計タスク完了後、プロジェクトが character-designer agent をデプロイ済みの場合（`.opencode/agents/character-designer.md` の存在確認）、`Agent(subagent_type: "character-designer", prompt: "プロジェクトディレクトリ：{dir}\nタスクタイプ：キャラクター設定\nクエリパラメータ：{キャラスケッチ+関係}")` を spawn してキャラクター設定と言語スタイルファイル作成を補助可能。agent が利用不可の場合は主スレッドが直接実行。

### Phase 3：シーン別写作

**プロジェクトファイル構造**：

```
{短編タイトル}/
├── 设定.md              ← Phase 2 成果物（对标概要含む）
├── 小节大纲.md          ← Phase 2 成果物
├── 正文.md              ← Phase 3 成果物
└── 对标/                ← 現在の短編参照ビュー（オプション）
    └── {書名}/
        ├── 拆文报告.md
        ├── 情节节点.md
        └── 写作手法.md
```

**分析結果の自動使用ルール**：写作実行前に必ず「对标コンテキスト読み込み」の順序で `{短編タイトル}/对标/{書名}/`、プロジェクトルート `拆文库/{書名}/`、`{短編タイトル}/拆文库/{書名}/` をスキャン。分析レポートを見つけた場合、「構造/感情/反転/写作手法」を技法参考として使用；構造化サブディレクトリを見つけた場合、現在の節の目標に最も関連するモジュールを検索。

> 用語説明：Phase 3 では「段」で叙事構造を区分（冒頭段/伏線段/昇格段/反転段/结尾段）、各段は複数の「節」（数字番号の beat）を含む。「シーン」は写作時の具体的な画面を指す。

**写前準備**（各シーン前に2ステップ実行、核心メソッドの具現化：感情目標の確認 → 技法モジュールの呼び出し）：
- **ステップ 1：記憶+呼び出し**：① 本シーンの目標感情ワード？② どの参考ファイルのどの技法を借鉴する？③ 具体的にどの段落で使う？答えられない → 先に参考資料を読み直してから執筆。`对标/` または `拆文库/` の構造化成果物がある場合、「对标コンテキスト読み込み」ルールで現在のシーンに最も関連する構造/感情/反転/写作手法モジュールを参考として検索し、「分析呼び出し概要」に書き込む
  <!-- cross-book-recall:trigger:tempo-section -->
  - **对标書が複数ある場合**：`references/cross-book-recall.md` 参照、副对标/参考对标は段階予算に応じて「副对标呼び出し概要」に；本文は概要のみを伝え、副書の文体や原文は伝えない
- **ステップ 2：指示確認**：一言で本シーンの写作意図を概括（感情+技法+適合段落）、確認後写作開始

**写作指示：三層織り込みでシーン別に写作し、大綱を翻訳しない。各シーンで読者と主人公が一緒に体験する。3次元（発生、知覚、反応）を同時に同一段落の連続本文に織り込み、次元で区分して書かない、「先に発生を書き、後から知覚を補う」方式は禁止。織り込み後も、ドラマユニット/画面ごとに段落区切りする必要あり：1段落は1つの完全な動作-情報変化、または1つの連続した推理/雰囲気/感情連鎖を担い、固定字数で強制的に分割しない。出力前に自然リズム再配置を行う：シーン/一件事が終わってから段落区切り；新しい動作、新しい手がかり、新しい会話、視線切替は別行に；完全な推理、雰囲気の敷き詰め、感情変化はやや長めの段落を保持可。高潮/溜飲/反転は短く締め、沈殿/推理/収束は長めに許可、爽ポイント beat は密に、場繋ぎ beat は疎に書き、全編同じ長さや同一閾値での段落区切りを避ける（writing-craft.md「疎密配分」参照）。主語リズム：段落頭または主語リセット時に主人公名を使用可；同一動作連鎖内では代名詞/省略を優先；キーとなる転換で再指名強調、連続した文/段落で不必要に主人公名を繰り返さない。句読点リズム：語気句読点スペクトルに従い実行、全体の句点化を避け、ランダムな疑問符/感嘆符の羅列も禁止；問い詰めは疑問符、爆発箇所は少数の感嘆符；ためらい、言いかけ、遮り、引き延ばしは動作停止、短文、改行で処理し、本文成果物では `……` / `——` / `—` / `--` を使用しない。叙述姿勢は深度限如此刻知覚にロック、因果説明のために飛び出さない/ネタバレ予告しない/読者の代わりにまとめ昇華しない（説教・神視点・作為感を除去、anti-ai パターン8/Gate G 参照）；感情は烈しくとも穏やかにせず、衝突は前に出し、爽ポイントは鋭く具体的に、台詞は棘を含ませ、極端な反応を書くことを恐れず「ほどほど」にしない（抑制を爽感とする題材（虐文/世情など）は除く、genre-catalog に従い抑制路線を取る）。**

#### Agent 呼び出し：narrative-writer

⚠️ **ハード制約：各節 ≥ 800 字 / 50-65 行**。
題材例外：爽文、溜飲、システム流などの高情報密度題材は ≥ 500 字/節に引き下げ可（genre-writing-formulas.md 各題材早見表参照）、ただし 500 字を下回ってはならない。
各節書き込み後に字数と行数を必ずカウント。800 字不足（高情報密度題材は 500 字不足）の節はスキップ不可、より多くのサブイベント/会話を追加して補ってから次節を書く。全編完了後の総文字数は ≥ 8000 字必須。
**字数カウントはクロスプラットフォームで実行可能にする：優先して Python 文字数統計を使用**：`for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done; "$PYBIN" -c "from pathlib import Path; print(len(Path('ファイルパス').read_text(encoding='utf-8')))"`。**直接 `python3` を呼ばない**、Windows では `python3` が Microsoft Store のプレースホルダーに飛び、exit 49 で静かに失敗する；上のプローブは `python3→python→py` で本当に使えるインタプリタを選ぶ。Windows / DeepSeek / Claude Code 環境ではモデル自身に字数を推定させない；`wc -m` は macOS/Linux の予備としてのみ使用、`wc -c`（バイト数）は禁止。現在の agent/ツール環境に Bash/Python 権限がない場合、「未完了の機械字数検証」と明確に宣言し、行数速算を暫定推定として使用し、字数ハード検証を通過したと主張してはならない。
**⚠️ 字数不足 = 章未完了。字数が基準に達していないのに章を終了してはならない。必ずシーンを展開し続けて基準達成まで書く。**

**節数保存**：正文の節数は節大纲計画節数と等しくなければならない。複数節を1節に統合してはならない。写作中にある節が独立して存在する必要がないとわかった場合、大綱段階で調整すべきであり、写作時に削減してはならない。

**節長達成フロー**：
1. **写作時**：三層織り込みで各サブイベントを書く——発生、知覚、反応を織り込んで同一段落の連続本文に、次元で区分して書かない
2. **字数不足時**（逐節カウント後）：以下の方法で補う（優先度高い順）：
   - サブイベントを追加（節大纲に戻って追加）
   - 会話を1ラウンド追加（writing-craft.md 会話権力パターン参照）
   - 回想フラッシュバック（1-2文の関連記憶）
   - 環境オブジェクト（動作を通じて出し、独立文にはしない）
   - **文字数稼ぎ禁止**：各追加は感情/伏線/没入感を推進しなければならず、水増し禁止。既存動作に描写を重ねるために「知覚層追加」「反応層追加」の方法を使ってはならない

**節長検証（分割写作、各バッチ書き込み後に実行）**：
分割写作：毎回 2-3 節を出力（2-3 節は Claude 単回出力の最適な叙事ウィンドウに相当、少なすぎるとコンテキストを浪費、多すぎると単節品質低下）、書き込み後、本バッチ全節の字数を一括チェック。
いずれかの節が < 800 字（高情報密度題材 < 500 字）の場合 → より多くのサブイベント/会話を追加して補ってから次バッチを書く。
未達の節をスキップしてはならない。

> バッチ検証はより効率的：一度に複数節を出力することで AI が叙事の一貫性を維持でき、
> バッチ後の統計は逐節停止より AI のテキスト生成特性に適合する。

> **節長速算**：平均 1行15字 × 55行 ≈ 825字。30行目でまだ 500 字に満たない場合、サブイベント数が不足している。サブイベントまたは会話の追加が必要。

各節は「三層織り込み」で写作（詳細は writing-craft.md 第 8 節）：各サブイベントは発生、知覚、反応の3次元を織り込んで同一段落の連続本文に、サブイベント合計 ≥150 字。次元織り込みは次元での段落区切りを意味しない——「先に発生を書き、後から知覚、反応を補う」積み重ね書き方は禁止；また1段落で終わらせるものでもなく、新しい動作/新しいオブジェクト/新しい情報/新しい会話で段落区切りする。長さは診断に過ぎず、まず完全なドラマユニットかどうかを判断；複数の動作/情報が混在している場合のみ分割、完全な推理、雰囲気、感情連鎖はやや長めの段落を保持できる。

**書き込み後、小节大纲.md と照合**：各サブイベントの3次元が全て織り込まれているか？本節の感情は適切か？伏線/アイテムは埋め込まれたか？節長 <800 字 → サブイベント/会話を追加してから次節を書く。

以下の構造で段落を分けて書く：

#### 第一段：冒頭（前 300-500 字）

**目標**：3文以内で読者を掴む。**必ず開篇フックを含む**（hooks-chapter.md からタイプを選択）。

**技法指示**：前 100 字のイベント密度 ≥ 3、背景説明はせず、直接イベント連鎖に入る。

**冒頭ゼロ環境ルール**（デフォルト適用；サスペンス、スリラー、災害、強雰囲気題材は例外可）：
- 前3文にイベントを伴わない環境描写（照明、天気、匂い、温度、インテリア）を禁止
- 前3文は以下4種のいずれかでなければならない：イベント / 会話 / 動作 / 情報爆弾
- 環境詳細はキャラクターの動作と知覚に織り込んで自然に出し、独立文にしてはならない；例外題材でも、環境は脅威、異常、または情報差を運ばなければならない
- チェック方法：前3文の主語をマーク、主語が環境オブジェクト（照明/廊下/部屋/天気）の場合、書き直し

冒頭テクニック：

| テクニック | 説明 | 例 |
|------|------|------|
| 衝突を前に出す | 第一文が矛盾 | 「離婚協議書が机の上に置かれていた。彼はもうサインしていた。」 |
| 情報差フック | 読者にキャラクターが知らない情報を与える | 「彼女は知らなかった。向かいに座る男がもう3度目を計画しているとは。」 |
| 異常行動 | 常識外の行動で好奇心を呼ぶ | 「彼女は婚約指輪をトイレに流した。」 |
| 転生の異常 | 転生後に前世では絶対にしないことをする | 「沈栀は心が灰燼に帰し、気力だけで仲人を見つけた。郭家のあの去勢された男に、私が嫁ぐ。」 |
| 超自然的身分 | 開篇で非人間的身分を明かす | 「私は現存する唯一の紅衣の厲鬼だ。自分がどうやって死んだのかも知らない。」 |
| 魂の傍観 | 魂の視点で死亡現場を描写 | 「私の遺体は透明な棺に横たわっていた。3人の兄が外で笑いながら言った。『彼女の演技は本当に上手い。』」 |
| サスペンス文 | 説明が必要な事実を投げかける | 「私が死んでから3日後、夫は WeChat のモーメンツに投稿した。」 |
| 身代わり結婚での見捨てられ | 不公正な運命を受け入れざるを得ない | 「3ヶ月後、私は皇后の嫡出公主の代わりに漠北へ和親の輿に乗った。」 |
| 没入式質問 | 直接読者に共感を呼びかける | 「あなたは深夜に、かけてはいけない電話を受けたことがあるか？」 |

#### 第二段：伏線（全文の 30-40%）

- アイテム/数字/習慣で絆を構築（詳細は emotional-methods.md「絆の敷設」）
- 最低3つの反転の手がかりを埋め込み、異なる節に分散
- 2-3節ごとに1つのフックを埋め込む（タイプは hooks-paragraph.md から選択）
- 節は数字で分割、各節は1つの情節ポイントを推進
- 感情強度は節ごとに増加、連続2節の感情変化なしは不可
- **貫通アイテムの第1回出現はこの段で完了必須**
- **敵対者の悪行は階段状に増加**（小悪→中悪、villain-and-reveal.md 参照）

#### 第三段：昇格（全文の 20-30%）

- 衝突は前段より昇格必須（強度/範囲/代価の少なくとも1次元が上昇）
- カウントダウンフックまたは代価フックを挿入して切迫感を生む
- フック密度を2節に1つに向上（題材段階分けは genre-writing-formulas.md 参照）
- ミスリード情報を埋め込み、読者に反転方向を誤認させる
- **数字/金額の増加を叙事ツールとして使用**（具体数字で曖昧な表現を代替、writing-craft.md 参照）
- **一動一静の交替**：各節に動あり静あり、連続暴力も連続静穏も不可

#### 第四段：反転（全文の 10-15%）

- 反転は1節内で完結させ、引き延ばさない
- 暴露後、前に敷いた手がかりが遡及できることを確認（読者が「なるほど」となる伏線を見つけられる）
- 反転節の感情衝撃強度は前の全節の最高値を超えなければならない
- **証拠品/証人/盗み聞き/玉ねぎ剥きで真実を暴露**（4方式は villain-and-reveal.md 参照）
- **貫通アイテムの第2回出現はこの段で完了必須**（意味が覆される）

#### 第五段：结尾（全文の 5-10%）

- 章末にフック必須（サスペンスまたは余韻）
- 静かな詳細で締める（アイテム、動作、短い言葉）、大きな抒情的段落は書かない
- 结尾方式は下表参照、emotional-methods.md「余韻の鈍痛」参考
- **貫通アイテムの第3回出現（回収の衝撃）**

结尾タイプ：

| タイプ | 効果 | 適した感情 |
|------|------|----------|
| 余韻式 | 言い切らず、読者に考えさせる | 切ない |
| 呼応式 | 首尾呼応、閉ループを形成 | 癒し、成長 |
| 開放式 | サスペンスを残す | 戦慄 |
| 反転の反転 | 结尾で小さな反転をもう一つ | 衝撃 |
| 金句式 | 一言で主題を言い当てる | 共鳴 |

### Phase 4：精密修正

`references/writing-workflow.md` の精密修正チェックリストを読み込んでチェックを完了。
重点：冒頭フック、感情曲線、反転伏線、各文の価値、フォーマット規範、AI 腔のチェック。

#### Agent 呼び出し：narrative-writer（AI臭除去）+ consistency-checker

精密修正段階で、プロジェクトが対応 agent をデプロイ済みの場合、以下を spawn 可能：
- `Agent(subagent_type: "narrative-writer", prompt: "プロジェクトディレクトリ：{dir}\nタスク説明：AI臭除去+フォーマットチェック\nチェック範囲：{本文ファイル}")` — AI臭除去（7 Gate）とフォーマット準拠チェックを実行
- `Agent(subagent_type: "consistency-checker", prompt: "プロジェクトディレクトリ：{dir}\nチェック範囲：{本文ファイル}\nチェックタイプ：事実衝突+伏線断線+キャラ属性不一致")` — 一貫性チェックを実行

agent が利用不可の場合は主スレッドが直接実行。

**本文清潔ルール**：
- 自己チェック（字数統計、禁用語スキャン、フォーマットチェック）はプロセス動作であり、結果は直接会話内で説明し、ファイルに格納しない
- **絶対に**自己チェック記録を本文ファイルの末尾に追加してはならない
- 本文内に `<!-- 自検 -->` または類似のチェックマークコメントを一切含めてはならない

通過しない → 補足に戻る。
