# 構造移行マッピングルール（短編）

Phase 3-S 短編構造移行の詳細マッピングルール。`分析庫/{書名}/` の短編分解成果物を `{短編タイトル}/` 短編プロジェクト構造に変換し、`story-short-write` Phase 3 がシームレスに継続執筆できるようにする。

> 長編移行ルールは `structure-mapping-long.md` を参照。

---

## 長編との主要な違い

| 観点 | 短編 | 長編 |
|------|------|------|
| 本文 | 単一ファイル `本文.md`、**章分割しない** | `本文/第XXX章_章名.md` の複数ファイル |
| 追跡ディレクトリ | **生成しない** `追跡/` | 生成する `追跡/`（伏線/時間線/キャラ状態/コンテキスト） |
| キャラ状態 | **生成しない** `追跡/キャラ状態.md` | 生成する、`character-state-reverse.md` で逆推 |
| アウトライン体系 | **生成しない** 巻綱、細綱 | 生成する `アウトライン/巻綱_第X巻.md` + `アウトライン/細綱_第N章.md` |
| アウトラインディレクトリ | **生成しない** `アウトライン/` ディレクトリ | 生成する |
| 継続執筆の連携 | story-short-write Phase 3（シーン単位の執筆） | story-long-write の日次更新サイクル |

**移行時に `追跡/`、`アウトライン/`、`本文/` などの長編ディレクトリを誤って作成しないこと。**

---

## 短編ターゲットプロジェクト構造

```
{短編タイトル}/
├── 設定.md              ← コアフレームワーク + ベンチマーク要約を含む
├── セクションアウトライン.md  ← 段落-セクション構造から逆推
├── 本文.md              ← 単一ファイルの全文本文
└── ベンチマーク/{書名}/    ← オプション：分解参照ビュー
    ├── 分解レポート.md
    ├── プロットノード.md
    └── ライティング技法.md
```

---

## マッピング概要

| 分解成果物 | 短編プロジェクトファイル | 変換方法 |
|---------|------------|---------|
| 原文全文（`分析庫/{書名}/原文/`） | `{タイトル}/本文.md` | 単一ファイル移行、`format-and-structure.md` に従ってフォーマット正規化（セクション区切り `###1.`、段落間は単一改行のみ、引用符はプロジェクト/プラットフォームの規約に統一）；原文はすでに完成原稿なので、**内容は書き換えず、フォーマットのみ正規化** |
| `分解レポート.md` のストーリー核/題材/ベンチマークフィールド | `{タイトル}/設定.md`（コアフレームワーク領域） | コアフレームワークを逆推（下記「設定.md 逆推ルール」参照）、`story-short-write/SKILL.md` のコアフレームワークテンプレートに準拠 |
| `プロットノード.md` の機能セグメント | `{タイトル}/セクションアウトライン.md` | セクションアウトラインを逆推（開始段/準備段/上昇段/反転段/終了段に分け、フックフィールドは `[未確定]` とマーク） |
| `分解レポート.md` + `ライティング技法.md` | `{タイトル}/設定.md`（ベンチマーク要約領域） | 構造/感情/反転/ライティング技法をベンチマーク要約に書き込む |
| `分析庫/{書名}/` 全体 | `{タイトル}/ベンチマーク/{書名}/` | オプション：参照ビューとしてコピー、継続執筆時に必要に応じて読み込み |

---

## 設定.md 逆推ルール

ターゲットファイルフォーマットは `story-short-write/SKILL.md` のコアフレームワークテンプレートに準拠し、2つのブロックに分ける：

### ブロック一：コアフレームワーク

`分解レポート.md` のストーリー核、構造区分、人物分析などのフィールドから抽出し、以下のテンプレートに記入する：

```markdown
## 短編コアフレームワーク

### 基本情報
- タイトル：{原書名}
- 目標文字数：{原文実際文字数} 字
- 目標プラットフォーム：{分解レポートから抽出、なければ [未確定]}
- 感情目標：{分解レポート「感情線/爆点分析」から読者の期待される感情を抽出}

### 一言梗概
{主人公 + 困難 + 反転 + 感情着地点（分解レポートのストーリー核から抽出）}

### コア反転
- 反転タイプ：{分解レポートの反転分析から抽出：アイデンティティ反転/視点反転/動機反転/時間線反転}
- 反転内容：{一言で説明}
- 伏線手がかり：{プロットノード中の「伏線」類ノードから抽出、最低3つ；不足時は [未確定] とマーク}

### 感情設計
- 開始感情：{感情曲線の最初のノードから抽出}（強度 {1-10}）
- 中盤感情：{中盤の感情ノード}（強度 {1-10}）
- 反転感情：{反転節の感情ピーク}（強度 {1-10}）
- 終了感情：{終了節の感情}（強度 {1-10}）

### キャラクタースケッチ
- 主人公：{一言キャラ設定、人物分析から抽出}
- キーキャラ：{一言キャラ設定}
- 関係：{キャラ間の関係}
```

> 不明確なフィールドには一律 `[未確定]` マークを付け、空白のままにしない。

### ブロック二：ベンチマーク要約

`分解レポート.md` と `ライティング技法.md` から抽出し、ベンチマーク要約ブロックとしてまとめる：

```markdown
## ベンチマーク要約：{原書名}

### ストーリー構造
{分解レポート「機能セグメント」フィールドから抽出、各セグメントの機能を概説}

### 感情リズム
{感情曲線/爆点分析から抽出、感情の推移とピーク位置を説明}

### コア反転メカニズム
{反転メカニズム分析から抽出、伏線経路を含む}

### 再利用可能なライティング技法
{ライティング技法.md または分解レポート「再利用可能な構造」フィールドから抽出、≥3 項目}
```

## セクションアウトライン.md 逆推ルール

`プロットノード.md` の機能セグメント構造から抽出し、短編の段落-セクション構造にマッピングする。

### 段落レベルマッピング

| 短編段落名 | 対応するプロットノード機能セグメント | 説明 |
|---------|----------------|------|
| 開始段 | 導入（主人公/世界/困難の提示） | 通常 1-2 セクション |
| 準備段 | 発展前期（衝突の蓄積/伏線配置） | 通常 2-4 セクション |
| 上昇段 | 発展後期（衝突の激化/誤解の深化） | 通常 2-3 セクション |
| 反転段 | クライマックス（コア反転の誘爆） | 通常 1-2 セクション、感情ピーク |
| 終了段 | 結末（収束/感情着地点） | 通常 1-2 セクション |

### セクション項目テンプレート

```markdown
## 開始段

### セクション 1
- コアイベント：{プロットノードから該当セグメントの主要プロットポイントを抽出}
- 感情目標：{対応する感情曲線ノードの感情語}
- 章頭フック：[未確定]
- 章末フック：[未確定]
- 参考文字数：{原文の対応段落の文字数から推定}
```

> フックフィールドは `[未確定]` とマークする——確実に抽出できないため、ユーザーまたは継続執筆時の記入に委ねる。

### セクション数の推測

原文の実際の文字数から推定：`総文字数 ÷ 1000 ≈ セクション数`（短編の参考範囲 8-15 セクション）。セクション数と本文の実際の段落構造が一致していることは品質チェックリストの必須項目。

## 本文.md フォーマット仕様

原文を単一ファイル `本文.md` に移行し、フォーマットは `format-and-structure.md` に従って正規化する：

| 仕様項目 | 要件 |
|--------|------|
| セクション区切り | `###1.` `###2.` `###3.`（短編汎用フォーマット；ユーザーがプラットフォームを指定した場合は `format-and-structure.md` のプラットフォーム上書き表に従って切り替え） |
| 段落分割 | 演劇的単位/カメラ/一事の終了で自然に区切る；固定文字数で強制分割しない；完全な推論、雰囲気、感情の連鎖はやや長めの段落を保持可、全体が同一長さになったり箇条書きのように細切れになるのを避ける |
| 段落間の空行 | 本文隣接段落間は **改行1つのみ `\n`** 許可、空行や `\n\n` は不可 |
| 会話引用符 | デフォルト `""` 半角二重引用符；知乎塩言プラットフォームでは `「」` 可 |
| インデント | インデントなし、全角/半角スペースを使用しない |
| Markdown | 本文段落中では `**` `*` `#` `---` などの Markdown 構文を使用しない（セクション区切りマークを除く） |

**原文の内容は変更せず**、フォーマットの正規化のみ行う（段落分割、引用符統一、セクション区切りマーク追加）。

---

## ベンチマーク参照ビュー（オプション）

`分析庫/{書名}/` 全体を `{タイトル}/ベンチマーク/{書名}/` にコピーし、継続執筆時のベンチマークコンテキスト読み込みに使用：

```
{タイトル}/ベンチマーク/{書名}/
├── 分解レポート.md
├── プロットノード.md
└── ライティング技法.md
```

このビューはオプション項目（`story-short-write/SKILL.md` で `ベンチマーク/` ディレクトリは「オプション」と記載）。デフォルトで生成することを推奨し、継続執筆時に自動で「ベンチマークコンテキスト読み込み」ルールに従って検索できるようにする。

## 品質チェックリスト

Phase 3-S 移行完了後に実行：

- [ ] `本文.md` 単一ファイルが存在し、フォーマットが `format-and-structure.md` に準拠（セクション区切り、段落分割/主語リズム、段落間は単一改行のみ、引用符形式）
- [ ] `設定.md` にコアフレームワークブロック + ベンチマーク要約ブロックが含まれ、コアフレームワークが `story-short-write/SKILL.md` テンプレートに準拠
- [ ] `セクションアウトライン.md` の節数が本文の実際の段落構造と一致
- [ ] すべての `[未確定]` マークが追加済み（不明確なフィールドは空白にしない）
- [ ] `追跡/`、`アウトライン/`、`本文/` などの長編専用ディレクトリを誤って作成していない
