# プロットフレームワーク

ネット小説創作で使用される3種のプロットフレームワーク。

---

## フレームワーク1：三幕式構造

ネット小説に適応した三幕式構造：「第一幕（設立）」「第二幕（対抗）」「第三幕（解決）」。

### 第一幕：設立（全体の約20%）

**機能**：
- 主人公と世界観を紹介する
- 初期の問題/目標を設定する
- 読者が読み続けたくなる最初のフックを提供する

**キーイベント**：
1. **日常の紹介**：主人公の最初の状態を示す
2. **きっかけの出来事**：主人公が日常を離れるきっかけ
3. **重要な決断**：主人公が新たな状況を受け入れるかどうかを決断する

**注意すべき問題**：
- 冒頭の爽点密度（最初の3章で読者を引き込む）
- 設定過多を避ける
- きっかけの出来事ははっきりと強いものでなければならない

### 第二幕：対抗（全体の約50%）

**機能**：
- 主人公が成長し、試練に立ち向かう過程
- 主な爽点はこの部分で解放される
- 伏線を敷き、キャラ同士の関係を深める

**キーイベント**：
1. **エネルギーの蓄積**：爽点蓄積の過程
2. **爽点の解放**：爽点爆発の瞬間
3. **伏線の敷設**：後続のプロットのための準備
4. **中だるみ回避**：爽点のバリエーションとリズムのコントロール

**第二幕でやってはいけないこと**：
- 爽点を解放しすぎない（期待値を使い果たしてしまう）
- 主軸を見失わない（サブプロットがメインプロットを圧迫する）
- 側面のキャラに時間を割きすぎない

### 第三幕：解決（全体の約30%）

**機能**：
- 核心対立を解決する
- 伏線をまとめて回収する
- 爽点を集中的に爆発させる

**キーイベント**：
1. **クライマックス前の爽点蓄積**：最終決戦前の盛り上がり
2. **爽点爆発**：爽点の連続爆発
3. **核心対立の解決**：大ボスの処理
4. **後日談**：生存者の行く末、伏線の整理

**第三幕でやってはいけないこと**：
- 爽点爆発後にダラダラと引き延ばさない
- 伏線を回収し忘れない
- ラストバトルはファイト感を出しすぎない

## フレームワーク2：起承転合

中国の伝統的な叙事構造であり、ネット小説の各章や各巻の構造に適している：

| 段階 | 単章内の機能 | 巻レベルでの機能 |
|-------|------------|-------------|
| 起：問題/状況を提示 | フックで読者を引き込む、核心対立を提示 | 巻のテーマと対立を設定 |
| 承：発展/深化 | 対立を深化させる、情報を開示する | 爽点を蓄積し、伏線を敷く |
| 転：反転/転換 | 情報の反転、局面の逆転 | 爽点爆発、期待値を解放 |
| 合：収束/伏線 | 暫定的な解決、新たなサスペンス | 巻末のフック、新たな対立を提示 |

**各段階の字数配分の目安**：
- 起：10-15%
- 承：35-45%
- 転：25-30%
- 合：10-15%

## フレームワーク3：英雄の旅

英雄の旅のネット小説への適応版。17段階を5段階に圧縮し、ネット小説のリズムに合わせる：

| 段階 | 原文（キャンベル） | ネット小説適応版 |
|------|-----------------|----------------|
| 出発 | 日常の世界への召喚 | 第一章 6000字以内で 1 セット完了。身分+チート+敵を設定 |
| 開始 | 日常を離れ、試練の世界へ | 10万字以内で第1幕を完了。新世界のルールを確立 |
| 試練 | 試練/味方/敵 | 爽点サイクルで推進。適時に爽点を解放 |
| 最深 | 最大の試練 | 巻末の爽点爆発。50-70万字で発生 |
| 帰還 | 宝物を持って帰る | 爽点爆発+伏線回収。後半10万字で集中回収 |
