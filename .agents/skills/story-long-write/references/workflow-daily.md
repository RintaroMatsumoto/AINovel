# workflow-daily.md：日更続写作業フロー

本ファイルは「日更続写」シーンの完全なガイド。SKILL.md から本ファイルにルーティングされた後、以下のフローで実行する。

> **日更準備手順**：各章写作前の3ステップ——状態選別 + 文風召回 + 意図確認。Step 2 逐章循環に埋め込む。
>
> Step 2 必読の四類参照資料：
> 1. `{参照書パス}/プロット/情绪模块.md`（読者需求 / 情緒引擎 + 再現可能モジュール；欠落時は下記「モジュール/リズム欠落」ルール：v12 は停止して修正、legacy のみフォールバック）
> 2. `{参照書パス}/プロット/节奏.md`（重要情報推進 + 情緒触動点 + 爆発リズム；欠落時は下記「モジュール/リズム欠落」ルール：v12 は停止して修正、legacy のみフォールバック）
> 3. `{参照書パス}/文风.md`（全書レベル ~4000 字、原文アンカー例文断片含む）
> 4. `{参照書パス}/章节/第K章_摘要.md`（本章の情緒/基調に合わせて1章選択）；同章に `第K章_深度拆解.md` が存在すれば追加読取、なければ黄金三章深度拆解/文風ファイルの参考可能技法にフォールバック
>
> 参照書パス検索：先 `{プロジェクト}/参照/{書名}/`、フォールバック `分析库/{書名}/`。
>
> **文風欠落**：本章の写作を停止し、その場で生成しない。エラー報告：「参照書 X に 文风.md がありません。`/story-long-analyze` で Stage 6 を実行して文風を生成し、その後 `/story-import` で同期してください。」
>
> **モジュール/リズム欠落**：v12 新契約の参照書に `プロット/情绪模块.md` または `プロット/节奏.md` がない場合、本章の準備を停止し、`/story-long-analyze` Stage 3+ の再実行または `/story-import` の再実行を促す；pre-v12 legacy 分析库のみ写作を継続可能、story-explorer は `gaps.legacy_deconstruction` + `gaps.module_missing` / `gaps.rhythm_missing` を記録し、順に低信頼度で `分析报告.md`、`文风.md` の参考可能技法、マッチ章摘要 / `プロット/故事线.md` にフォールバック。
>
> **衝突ルール**：`プロット/情绪模块.md` と `プロット/节奏.md` は情緒とリズムの canonical / 権威ソース；`分析报告.md`、`プロット/故事线.md` は投影摘要；`文风.md` はスタイルのみを管轄。摘要または文風が権威モジュール/リズムと衝突する場合、`gaps.conflict` を保持し、本文の意図は権威ファイルに従う。
>
> **参照無しプロジェクト**：Step 2.3 をスキップし、2.4 意図確認で「参照参考なし」とマーク。存在しない文風を読まず、ブロックせず、警告しない。
>
> **参照書が複数ある場合**：`設定/题材定位.md` から `主参照书` フィールドを読み取る；欠落時は `参照/` 下の辞書順最初の1冊を使用し、ユーザーにフィールドの補完を促す。
>
> 完全な執筆前準備ロジックは `SKILL.md` の Phase 4 参照。

---

## 適用条件

- プロジェクトに既に `本文/` と `追跡/` ディレクトリがある
- ユーザーが「日更」「続写」「続けて書く」と言った
- 目標：1セッションで2-3章（4000-9000字）を書く

---

## Step 1：高速コンテキストロード

**オプション：story-explorer agent を使用したバッチコンテキストロード**。プロジェクトに story-explorer agent がデプロイされている場合（`.claude/agents/story-explorer.md` の存在をチェック）、`Agent(subagent_type: "story-explorer", prompt: "プロジェクトディレクトリ：{dir}\nクエリタイプ：context_load\nクエリパラメータ：第 {N} 章を書く準備")` で `context_load` クエリを実行し、一度にすべての写作コンテキストを取得できる。spawn が戻ったらその results を直接使用し、下記の手動ロード手順をスキップする。agent が使用不可または不完全な場合は、下記の手動ロードにフォールバック。

手動ロード（デフォルト方式）：

| 番号 | ファイル | 用途 | 存在しない場合 |
|------|------|------|-----------|
| 1 | `追跡/上下文.md` | 前回の写作進捗サマリー | `追跡/伏線.md` + `追跡/時間線.md` から再構築 |
| 2 | `追跡/伏線.md` | 未回収伏線リスト | スキップ |
| 3 | `追跡/時間線.md` | 現在のイベント時系列 | スキップ（写作時に本文から推測） |
| 4 | `大綱/細綱_第{N}章.md` | 本章の写作計画 | **必ず先に補完**、スキップ不可 |

**必要に応じてキャラファイルをロード**：細綱から本章に関わるキャラ名を抽出し、必要に応じて `設定/キャラ/{キャラ名}.md` をロード。細綱にキャラが記載されていない場合はスキップ。

**必要に応じて創作公式をロード**：写作中に創作公式の制約を参照する必要がある場合（期待感公式、爽点公式、情報差公式など）、`references/genre-writing-formulas.md` をロード。デフォルトではロードせず、条件なしで1500+行のファイルをロードしてトークンを浪費するのを避ける。

### 既書内容階層化摘要

プロジェクトが30章を超えた場合、`追跡/上下文.md` の既書内容摘要は三層構造で編成し、初期の章を圧縮し、直近の詳細を保持：

| 階層 | 粒度 | フォーマット | 保守タイミング |
|------|------|----------|----------|
| **直近5章詳記** | 直近5章の逐章摘要 | 既存フォーマットを保持（各章一段：イベント+状態変化+伏線） | 各章執筆後に更新 |
| **十概要** | 10章ごとに一段の概要 | `章範囲 | 既書核心イベント | キャラ状態変化` | 10章書き終えるごとに一段生成 |
| **巻級総覧** | 各巻を一文で総括 | `巻名 | 既書主線進捗 | 重要転換` | 各巻終了時に生成 |

**例（50章プロジェクト）：**
```markdown
## 直近5章詳記（第46-50章）
第46章：主人公が秘境に入り、上古遺跡を発見...
第47章：守護獣に遭遇、辛勝して傳承を獲得...
...

## 十概要
第1-10章 | 主人公が金手指を覚醒、修行学院に入学 | 廃柴から内門弟子へ
第11-20章 | 学院大会で天才ライバルを撃破 | 長老の注目を獲得、実力突破
第21-30章 | 学院を離れ、秘境を探索 | 身世の手がかりを発見、盟友と契約
第31-40章 | 勢力闘争に巻き込まれ、身分を暴露 | 追われ、実力再突破
第41-50章 | 追手を返り討ち、新マップへ | 血脈傳承を確認、上界へ

## 巻級総覧
第一巻・覚醒 | 廃柴逆襲から天才へ | 金手指覚醒、身世が初めて兆しを見せる
```

> **初回日更のフォールバック**：`追跡/` ディレクトリ配下のファイルがすべて空または存在しない場合（Phase 3 完了直後で日更未経験）、追加で `大綱/卷纲_当前卷.md` と最新1章の本文をロードしてコンテキストを再構築。

> **次の章番号 N の決定**：`追跡/上下文.md` の「最終完了章」フィールドから読み取る。ファイルが存在しない場合、`本文/` ディレクトリで最も番号が大きい章をスキャンし +1 する。

今回の写作範囲を決定後、直接 Step 2 に入る。「続けるか」の確認は行わない。K のデフォルトは2-3章。ユーザーが「1章だけ」「日更3章」「逐章確認」と明示した場合はユーザーの要求に従う。章番号の衝突、細綱の欠落、要求範囲が既存の細綱を超えている、ユーザーの要求が大綱/追跡を変更する、またはその他書き間違いにつながる致命的な情報がある場合のみ、確認のために一時停止する。

## Step 2：直列バッチ写作

一回で複数章の細綱をロードするが、**メインセッション内で直列に逐章写作しなければならない**：複数章を同時に複数のサブエージェントに並列発行してはいけない。長編の章は前章の本文と追跡ファイルに依存するため、並列ではコンテキストの断絶、追跡の上書き、タイトルの重複チェック失敗が発生する。

**バッチ継続ルール**：本 Step に入った後、「続けて」「続写」「日更」は現在の日更バッチフローを継続することを示す。これらの語を Step 2.2/Step 2.3 の直接本文続写のスキップと解釈してはならない。また各章の間で続けるかどうかを繰り返し尋ねてはならない（ユーザーが明確に逐章確認を要求している場合または致命的な問題が発生した場合を除く）。

1. **細綱の読み取り**：今回書く2-3章の細綱をロード。新版細綱がある場合は「内容概括（起因/発展/転機/山場/結末）」「プロット安排（主線/副線/事件線/感情線/論理線）」「人物関係と登場順」「プロット詳細化」「結末設定とフック」を優先読取；旧版細綱にこれらのフィールドがない場合はブロックせず、核心イベント、プロットポイントシーケンス、目標感情、章首/章尾フック、字数目標にフォールバック。
2. **逐章実行**（以下の各ステップを各章のループ内で実行）：
   - 細綱を読む → 必要に応じてキャラ設定をロード
   - **2.1 タイトル事前チェック**：既存の章タイトルをスキャン；本章のタイトルが同名または明らかに重複する場合、まず本章の核心イベントに従って改名し、同時に細綱タイトルと本文ファイル名を同期
   - **2.2 状態選別**：各章開始前に、以下のソースが今回のワークフロー内で既に読み取りまたは更新されたことを確認する：本章細綱、前章本文（または前章に書き込まれた本文）、`追跡/上下文.md`、`追跡/伏線.md`、`追跡/時間線.md`；関係キャラがいる場合、`追跡/キャラ状態.md` または対応する `設定/キャラ/{キャラ名}.md` のソースも確認する。「既にロード済み」とは今回のワークフロー内で実際に読み取り/更新されたファイルのみを指し、ソース不明のチャット記憶で代替してはならない。キャラの最新状態は優先的に `追跡/キャラ状態.md` から選別（存在しない場合はキャラ設定から推測）、回収/推進待ちの伏線は `追跡/伏線.md` から選別；細綱が存在しない場合も下記の補完フローに従って処理し、直接本文を書くことは許されない
   - **2.3 参照モジュール/リズム/文風召回**：
     - story-explorer の `benchmark_style_load` query_type を呼び出し（入力：プロジェクトディレクトリ + 本章目標感情 + 本章爽点タイプ + 本章目標字数）で一度に以下を取得：`{style_profile_path, style_profile_summary, selected_emotion_module, rhythm_reference, module_source_path, rhythm_source_path, matched_chapter_K, matched_chapter_techniques, anchor_excerpts, gaps}`
     - `gaps.no_benchmark: true` → 文風召回をスキップ、2.4 意図確認で「参照参考なし」とマーク
     - `gaps.missing_primary_contract: true` → 本章の準備を停止、`repair_action` に従い `/story-long-analyze` Stage 3+ の再実行または `/story-import` の再実行を促す；narrative-writer に進んではならない
     - legacy の `gaps.module_missing: true` → 写作を継続；`selected_emotion_module` には `分析报告.md` の読者需求 / 情緒引擎、`文风.md` の参考可能技法、またはマッチ章摘要のフォールバック摘要を使用；それでもなければ「無」と書く
     - legacy の `gaps.rhythm_missing: true` → 写作を継続；`rhythm_reference` には `分析报告.md` のリズムと情緒触動点、マッチ章摘要、または `プロット/故事线.md` のフォールバック摘要を使用；それでもなければ「無」と書く
     - `gaps.conflict` または `gaps.module_rhythm_conflict: true` → 意図確認で衝突を説明し、`プロット/情绪模块.md` / `プロット/节奏.md` の権威優先順位に従って実行；`文风.md` が感情/リズム目標を上書きしてはならない
     - `gaps.profile_missing: true` → 上記の fail-fast フローに従い停止
     - `gaps.profile_degenerate: true`（文風使用不可）→ 文風をスキップ、デフォルト Gates 写作に戻る
     - `gaps.tone_match_failed: true` → 全書文風のみを使用して写作、matched_chapter は使用しない
     - それ以外は `style_profile_path`、`style_profile_summary`、`selected_emotion_module`、`rhythm_reference`、`module_source_path`、`rhythm_source_path`、`matched_chapter_K`、`matched_chapter_techniques`、`anchor_excerpts` をそのまま Step 2 末尾の narrative-writer spawn prompt に渡す；`selected_emotion_module` は感情目標に、`rhythm_reference` はリズム/爆発配置に、`matched_chapter_techniques` は「文風召回指令」に使用。執筆前準備記録は `gaps` の原値を保持する必要があり、特に `gaps.module_missing`、`gaps.rhythm_missing`、`gaps.conflict`、`gaps.matched_deep_dive_missing`；`matched_deep_dive_missing` が true の場合、文風召回指令に明確に「同章深度分解欠落、黄金三章/文風技巧にフォールバック済み」と書き、その後のレポートで false に反転してはならない
     - **story-explorer がない場合の降格**：メインセッションで手動により参照書パスを検索、まず `プロット/情绪模块.md` を読んで `selected_emotion_module` を選択、次に `プロット/节奏.md` を読んで `rhythm_reference` を選択、次に `文风.md` + grep `章节/*_摘要.md` の「基調」フィールドでマッチ章を検索、その後対応する `第K章_摘要.md` を読取；`第K章_深度拆解.md` が存在しない場合、`第1-3章_深度拆解.md` から本章の基調に最も近い章に変更。モジュール/リズムファイル欠落時はまず v12 vs legacy を判定：v12 は停止して修正、legacy のみ上記のフォールバックを継続
   - **2.4 意図確認**：細綱の「目標感情」フィールドから本章の感情目標を確認。状態選別結果 + `selected_emotion_module` + `rhythm_reference` + 文風召回出力を統合し、一文で本章の意図を書く（感情+リズム+モジュール+文風指令）。新版細綱が存在する場合、意図確認は明示的に以下を組み込む：内容概括が起承転合を決定、プロット安排が主線/副線/事件線/感情線/論理線の取捨を決定、人物関係と登場順がカメラの投入順を決定、プロット詳細化が代価の実行/収益の実行を決定、結末設定とフックが章末の継承を決定；さらに二つのクラフトを実施——① 発展/転機=爽点(山場)の布石蓄勢、爽点を出す前に識別可能な危機/期待を铺く（plot-emotion-system 逆推法、铺かない=空洞）；② 格好つけ/打顔/暴露章では 視点/情報差を 登場順 のその場の脇役を通じて差別化された反応に増幅する（plot-core-methods 情報差×人間×感情/集団衝撃）。例：「速いリズム打顔——起因=請求書暴露、論理線=発見→問い詰め→反証→代償の公表；M03‘情報差反殺’の読者期待を再現、重要情報は先に抑えてから爆発、爆発後は一段の冷却で次のフックにつなぐ；句読点は文風の停止リズムに従い、会話のサブテキストは質問に答えないで使用。」
   - 本文を書く → **字数検証（優先 Python 文字カウント、`wc -m` は Unix の予備のみ、目標の90%未満は強制拡充）** → フック/爽点チェック → **本文メタ情報スキャン** → 禁止語句スキャン
     - **本文メタ情報スキャン**：タイトル行以外に `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏線|細綱|读者` が出現してはならない。これらの語は写作/エンジニアリングメタ情報であり、キャラがその時点で知覚可能なイベントアンカーまたは相対時間に変更しなければならない；例えば「第一章のあの三秒の開火より痛い」は「あの三秒の開火より痛い」に変更。キャラが物語世界内で実際に「第X章」を読み/議論する場合、または実際に作者/読者として読者の身分について話す場合は例外。
   - 各章執筆後**直ちに**以下のファイルを更新：
     - `追跡/伏線.md`（新規/回収伏線）
     - `追跡/時間線.md`（イベント時系列を記録）
     - `追跡/キャラ状態.md`（本章がキャラの状態変化——身分、能力、関係、公衆イメージ——を引き起こした場合、対応キャラの項目を更新し変更記録を追加）
     - `追跡/上下文.md`（進捗メタ情報のみ更新：現在位置+既写字数+今回の変更、詳細なキャラ状態/伏線内容は書かない）
   - **品質チェックプロンプト**（オプション）：本章の写作が完了。一貫性チェックが必要な場合、`/story-review lean` を実行。バッチ写作モードではこのステップをスキップし、すべて書き終えた後に一括審査する。
3. **中断しないが並列もしない**：一章書き終えてもユーザーに尋ねず、直接次の章を書く（ユーザーが逐章確認を要求した場合を除く）；次の章は前章に書き込まれた本文と追跡更新を読み取ってから開始する。

**資料研究（必要に応じて）**：写作中に検証が必要な外部事実（歴史年代、地理的位置、職業の詳細など）に遭遇した場合、写作を一時停止し、`story-researcher` agent を起動して検索し、`参考资料/` ディレクトリに出力する。研究が完了したら写作を再開する。

## Step 3：品質チェック

バッチ写作終了後、今回のすべての新規書き下ろし章に対して Phase 5 品質チェックを実行（少なくとも以下を含む）：

1. **禁止語句スキャン**：`references/banned-words.md` を对照、一次語はヒット即置換
2. **タイトル重複チェック**：今回の新規書き下ろし章と既存タイトルを集計；同名または明らかに重複するものを発見した場合、対応する細綱と本文ファイルに戻って一括リネーム
3. **本文メタ情報スキャン**：タイトル行以外に `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏線|細綱|读者` といった写作エンジニアリング語が混入していないかチェック、ヒットしたらシーン内表現に変更；物語内で実際に「第X章」を読み/議論する文脈、または実際の読者としての身分に関する文脈は除く
4. **フックチェック**：各章の章末にフックがあるか；新版細綱に「結末設定とフック」がある場合、本文が収束状態、未解決問題、次章への推進力を実行しているかチェック
5. **細綱との対照チェック**（本文が細綱通りに書かれているか）：新版細綱が存在する場合、本文が内容概括の五段式、プロット安排のマルチライン、人物関係変化/登場順、代価の実行/収益の実行を消費しているかチェック；さらに三条のクラフト実行チェック（未达标→修正）：① 爽点を出す前に識別可能な危機/期待布石段落があるか？指摘できない=空洞 → Step 2 に戻り布石プロットポイントを補充（plot-emotion-system 逆推法）；② 格好つけ/打顔/暴露章でその場の脇役の差別化反応（集団衝撃/各異）を書いているか、それとも主人公の動作だけか？ない → その場の脇役反応を補充（plot-core-methods）；③ 詳略が目的語（爽点/セールスポイントは展開、経過は軽く流す、情報密度を交替）に従っているか、それとも均等に水増ししているか？均等 → 経過を削除、爽点点を拡充。旧版細綱は核心イベント、目標感情、章首/章尾フック、字数目標のみを照合
6. **伏線チェック（今回の増分のみ）**：今回新規追加/推進/回収した伏線が `追跡/伏線.md` に書き込まれ、状態が更新されたことのみ確認；日更フローですべてのセッションを読通したり全本文をスキャンして全量伏線監査を行ってはならない。全量伏線監査は `/story-review` またはユーザーが明確に「全面的に伏線をチェックして」と要求した場合のみ実行
7. **句読点確定收尾**：今回のすべての新規書き下ろし本文ファイルに対して `node scripts/normalize-punctuation.js 本文/第XXX章_*.md` を実行（書き込みモード、デフォルト `--quote-mode keep`）、本文内の `……`、破線 `——`/`—`、二重ハイフン `--` および独立行 `---` を確定的に除去し、長編が百章を超えた後に横線や長い省略が蓄積するのを避ける。スクリプトはもはや会話の中断破線を保持しない；数値範囲は中国語の接続詞に書き換えられ、塩言の「」は影響を受けない。**実行主体**：narrative-writer agent は本スクリプトを実行しない；メインセッションが agent 書き終えて戻った後、実際に書き込まれた本文ファイルのパスに対して実行する（ファイル名は書き終えて初めて確定する `第XXX章_章名.md`）。

> 完全な Phase 5 チェックリストは SKILL.md Phase 5 参照。

## Step 4：進捗摘要

`追跡/上下文.md` を更新（各章完了時に増分更新済み、ここで最終集計を行う）：

```markdown
## 写作進捗

- 最終完了章：第 {N} 章
- 更新日時：{日付}
- 本期完了：{K} 章、計 {X} 字

## 現在の状態

- アクティブ伏線：{N} 件（詳細は 追跡/伏線.md 参照）
- キャラ状態：最新変更 {キャラ名}（詳細は 追跡/キャラ状態.md 参照）
- 次章細綱状態：{既存/要補完}
- 注意事項：{覚えておくべき重要な決定や変更}
```

## 細綱欠落補完フロー

細綱が存在しないことを検出した場合、スキップはできない。以下の手順で補完する：

1. `大綱/卷纲_当前卷.md` をロード（本章に対応するイベント計画）
2. 本章に関わる `設定/キャラ/{キャラ名}.md` をロード（キャラ状態）
3. 最新1章の本文を読み取る（プロットの接続）
4. SKILL.md Phase 3 の新版細綱テンプレートに従って本章の細綱を補完し、内容概括、プロット安排、人物関係/登場順、プロット詳細化、結末設定を補充；巻綱/本文/設定から確認できないフィールドは `[未確定]` と書き、捏造しない
5. 補完完了後、Step 2 の写作を継続

## よくある問題

| 問題 | 処理 |
|------|------|
| 細綱が存在しない | 上記「細綱欠落補完フロー」を実行 |
| 旧版細綱に新版設計図フィールドがない | 日更をブロックしない；今回の改綱/補綱時に新版テンプレートで記入、不明項目は `[未確定]` と記入 |
| 追跡ファイルが空 | 正常に継続、写作中に徐々に埋める |
| ユーザーが大綱の変更を要求 | 「大綱を変更すると後続の細綱に影響します」と注意、確認後修正、影響を受ける細綱をマーク |
| 巻末に達した | ユーザーに「現在の巻が完了しました。新巻を開始しますか？」と通知 |
| ユーザーがバッチ写作を中断 | 現在の章を保存、追跡ファイルは更新済み、次回は中断箇所から継続 |
