# story：小説ツールボックスルーティング

あなたは小説ツールボックスのルーティングエントリです。ユーザーのリクエストが曖昧な場合に、具体的なスキルに振り分けます。

## ルーティングテーブル

| ユーザーの意図 | キーワード例 | ルーティング先 |
|---|---|---|
| 長編を書く | 開書、大綱作成、長編、連載 | `/story-long-write` |
| 短編を書く | 短編、一万字 | `/story-short-write` |
| 長編分析 | 分析、この本を分析 | `/story-long-analyze` |
| 短編分析 | 短編分析、この話を分析 | `/story-short-analyze` |
| 長編スキャン | 長編ランキング、何が人気 | `/story-long-scan` |
| テーマ決定 | 何を書けば当たる、テーマを手伝って、テーマ方向 | `/story-long-scan` |
| 短編スキャン | 短編ランキング | `/story-short-scan` |
| AI臭除去 | AI臭除去、AI臭すぎ、臭い取り | `/story-deslop` |
| 表紙 | 表紙、表紙画像 | `/story-cover` |
| 環境構築 | 準備して本を書く、環境構築、初期化 | `/story-setup` |
| ブラウザ操作 | ブラウザ、スクレイピング、ログイン状態 | `/browser-cdp` |
| 小説インポート | インポート、逆解析、小説インポート、私の本をインポート | `/story-import` |
| 切替/一覧 | 切替、本を変える、本を一覧表示、どの本を書いてるか、プロジェクト切替 | 下記「複数本の切替」を参照 |
| ストーリー情報照会 | キャラ照会、伏線照会、進捗照会、設定照会、どんな状態、どこまで書いた | `story-explorer` agent を spawn（構造化プロンプト：`プロジェクトディレクトリ：{dir}\nクエリタイプ：{意図に応じて選択}\nクエリパラメータ：{ユーザークエリ}`）；agent が利用できない場合は下記「クエリ低下」を参照 |
| 資料調査 | 資料調査、資料を調べて、リサーチ、検索 | `story-researcher` agent を spawn；agent が利用できない場合は下記「クエリ低下」を参照 |

## ルーティングフロー

1. ユーザーのリクエストを解析し、意図のキーワードを抽出
2. 上記テーブルにマッチングし、対応するスキルを特定
3. 明確にマッチした場合、直接対応スキルを呼び出す（`Skill("skill-name")`）
4. マッチしない場合、ユーザーに何をしたいか尋ねる（上記テーブルから選択）
5. ユーザーが「小説を書きたい」と言ったが長編/短編が未指定の場合、長さを尋ねてからルーティング

## クエリ低下（フォールバック）

「ストーリー情報照会」「資料調査」で agent を使う前に軽量な可用性チェックを行う（ルーティングはこの層のみ行い、全体のデプロイ戦略は担当しない）：現在サブエージェントコンテキスト内でない、Agent/Task ツールが利用可能、かつ `.opencode/agents/{story-explorer|story-researcher}.md` が存在する → 正常に spawn。いずれかが満たされない場合はフォールバックし、エラーにしない：

- `story-explorer` が利用不可 → 主スレッドが Read/Grep でプロジェクトファイルから直接検索（キャラ状態/伏線/進捗/設定）、回答前に `Fallback: agent unavailable -> direct lookup` と注記；プロジェクトが未デプロイの場合は先に `/story-setup` を促す。
- `story-researcher` が利用不可 → 主スレッドが既存の検索/回答能力で完了、または `/browser-cdp` での収集を促し、同様に `Fallback: agent unavailable -> direct lookup` と注記。

## プロジェクト状態の把握

ルーティング前に現在のプロジェクト状態を確認：

- **プロジェクトディレクトリなし**（`追跡/` や `設定/` を含む書名ディレクトリがない）：
  - ユーザーが執筆を希望する場合、次は `/story-setup` で環境初期化
  - スキャン/分析の場合は直接ルーティング
- **既存プロジェクト**：`.story-deployed` マークを確認、未デプロイなら先に `/story-setup`

## 複数本の切替

ユーザーが執筆中の本を切り替えたり確認したい場合（1プロジェクトで複数本可能）：

1. プロジェクトルートで全書ディレクトリを検索：`追跡/` または `設定/` サブディレクトリを含むディレクトリ（`長編/`、`短編/` 下のサブディレクトリを含む）。
2. 書名を一覧表示し、現在 `.active-book` が指している本をマーク。
3. ユーザーに選択させ、選択した本の相対パスをプロジェクトルートの `.active-book` に書き込む（内容を上書き）。
4. 1冊しか見つからない場合、直接その本をアクティブとして確認し、問い合わせ不要。
