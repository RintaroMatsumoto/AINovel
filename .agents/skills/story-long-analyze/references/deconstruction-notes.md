# 分析ノート

`story-long-analyze` パイプライン Stage 6（全量集約）の統合ノート。文体分析、構造抽出、伏線マップ等の全分析次元を集約し、最終的な分析レポートとプロットノードを生成するための統合判断の補助とする。

---

## 統合判断の指針

### 1. 文体ラベルの集約

各分析モジュールの文体判断を統一的に集約し、矛盾なく最終文体ラベルを決定する。

- 全モジュールが一致する文体特徴 → 直接結果ラベルとして出力
- モジュール間で矛盾する文体特徴 → 以下の優先順位で判断：
  1. 全文精読モジュールの判断を優先
  2. 複数モジュールが一致する判断を優先
  3. 黄金三章の判断を後続章の判断より優先
- 文体に変化がある作品 → 「可変文体」とマークし、変化点を記録

### 2. 構造抽出の精度

- 構造区切りは明確なストーリーイベントに基づき判断し、文字数の等分による機械的区分を避ける
- 構造区切りに複数の可能性がある場合 → 最も合理的な 2 つの判断を併記
- 「三幕 vs 五段 vs 四部」の判断で迷った場合 → 三幕をデフォルトとしてマークし、他の可能性を注釈として付記

### 3. 伏線マップの整合性

- 伏線の設置と回収の因果関係を検証する
- 設置されたが未回収の伏線 → 「未回収」とマーク、合理的な回収位置を推測
- 回収されたが設置のない伏線（唐突な情報） → 「未設置回収」とマーク
- 同一伏線に複数の回収の可能性 → 最も可能性の高い回収経路をマーク

### 4. キャラ弧の一貫性

- キャラの行動が性格ラベルや動機と矛盾していないか確認
- キャラの成長/変化点を記録
- 合理性のないキャラの行動 → 「性格ブレ」とマーク

### 5. 感情リズムと爽点分布の対応関係

- 爽点の出現位置と感情ピークが対応していることを検証
- 爽点密集度と感情リズムのテンポの一致度を確認
- 爽点がないのに感情ピークがある位置 → 爽点タイプの見落としの可能性

## 分析ノートのフォーマット

分析プロセス中、以下のフォーマットでノートを記録する：

```markdown
### {章/範囲}

**文体観察**：{観察内容}

**構造観察**：{観察内容}

**伏線候補**：{伏線内容} [{タイプ}] → {疑わしい回収位置}

**キャラ観察**：{キャラ} → {行動/変化の観察}

**感情マーカー**：{位置} 感情 = {感情語}（強度 {1-10}）

**未確定**：{疑問点}
```

## 全量集約時の品質フィルター

以下の品質問題が検出された場合、分析レポート中で明示的にマークする：

| 問題タイプ | マーク方法 | 備考 |
|---------|---------|------|
| データ出所不明 | `[出所不明]` | 推測に基づく判断 |
| モジュール間矛盾 | `[矛盾：A vs B]` | 両方の判断を併記 |
| サンプル不足 | `[サンプル不足]` | 走査範囲が限定的なため判断が不十分 |
| 未確定情報 | `[未確定]` | 現時点で結論が出せない |
