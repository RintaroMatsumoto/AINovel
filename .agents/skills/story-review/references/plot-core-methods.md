# プロットコア手法

`story-review` プロット審査員の分析方法。ストーリー構造の合理性、爽点の分布、伏線の設計を評価する。

---

## 分析フレームワーク

全体的なスコアリング方法については `quality-rubric.md` を参照。

### 1. 構造整合性分析

計画に基づき、各章の機能が計画と一致しているかチェック。

**チェックポイント：**
- 各章は全体構造の中で期待される役割を果たしているか
- 章間の接続に断裂がないか
- 爽点の配置は計画通りか

### 2. 因果連鎖分析

各主要イベント間の因果関係を検証。

**手法：**
- 各章の主要イベントに対して「なぜこのイベントが起きたか」の原因をたどる
- 原因が前章にない、または合理的でない → 断裂点とマーク
- 各イベントに自然な結果があるか確認（結果が放置されていないか）

### 3. 爽点分布分析

全爽点をリストアップし、強度・密度・タイプ分布を評価。

**基準：**
| 指標 | 良好 | 要注意 |
|------|------|--------|
| 爽点密度 | 3〜5 章ごとに小さな爽点、7〜10 章ごとに大きな爽点 | 10 章以上爽点がない |
| 強度変化 | 爽点強度が徐々に上がる | 最初に強い爽点、後が弱い |
| タイプ分布 | 逆転 + 打顔 + 収穫 + 感情が混在 | 単一タイプのみ |
| 爽点前の伏線 | 爽点ごとに十分な期待構築がある | 爽点が唐突に出現 |

### 4. リズム分析

全体的な張弛リズムを評価。

**手法：**
- 各章の緊張度を 1〜10 で記録
- 連続する高緊張区間の長さを評価（3 章を超える高緊張持続は読者の疲労につながる）
- 弛緩区間の長さを評価（2 章超の連続弛緩は読者の離脱につながる）

---

## 典型的な問題と改善の方向性

### 問題一：爽点空白区間
- **症状**：連続する章に爽点がない
- **改善**：
  - 中間に小さな爽点を追加（例：脇役の小さな逆転、情報の暴露）
  - 爽点前の期待構築が長すぎる場合、爽点を前倒しする
  - 爽点がない区間は情報密度や感情の深みで補う

### 問題二：爽点の強度曲線がフラット
- **症状**：爽点の強度に変化がなく、クライマックスの爽点が最初の爽点よりも強くない
- **改善**：
  - 前期の爽点強度を抑え、後期の爽点強度を上げる
  - より強い爽点を追加（賭けの規模を拡大、犠牲を増やす、反転幅を大きくする）
  - 爽点の組み合わせ（連続爽点 = 複数の爽点タイプの重ね合わせ）

### 問題三：伏線回収漏れ
- **症状**：設置された伏線に回収がない
- **改善**：
  - 回収位置を追加するか、未回収の伏線を削除する
  - 伏線の回収を後続のプロットに組み込む
  - 削除できない伏線はオープンエンドや続編への伏線としてマーク

### 問題四：因果断裂
- **症状**：イベントに合理的な原因または結果がない
- **改善**：
  - 原因となるイベントを追加するか、原因を前方の章に遡らせる
  - イベントに自然な結果を追加する
  - 不合理なイベントを削除するか、合理性の高いイベントに置き換える
